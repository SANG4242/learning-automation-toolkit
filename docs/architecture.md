# 从 Hub 到课程笔记：上下文、插件和工具怎样配合

## 从实际使用中形成

我在整个大二学年的课程学习中使用这套工具，并在持续使用、提问、复习和整理中调整它。最初只是文档转图，后来需要保留课堂讲授、查找时间、制作图文笔记，于是逐步补上转录、概述、对齐、画面和课程上下文。

工具增加以后，关键问题不再只是“某个脚本能否运行”，还包括 AI 从哪里知道有哪些工具、什么时候读哪些资料、怎样遵循课程要求，以及下一次对话如何继续。

## 六层职责

```text
Hub 入口与领域导航
  ├─ 工具调用指引 → 工具自己的 README → 脚本 / 模型 / 外部程序
  └─ 课程或项目 .agent/memory.md
       ├─ progress.md：当前任务、状态、下一步
       ├─ completed_tasks_log.md：完成历史与答疑
       ├─ plugins/：已经安装、按任务触发的流程
       ├─ context/：课程特化和长期资料
       └─ 资料索引 → 课件 / ASR原文 / 概述 / 笔记 / 图片
```

### 1. Hub：给 AI 地图，而不是一次塞入全部材料

Hub 的入口给出领域、路由关键词和读取时机。AI 先定位课程或工具入口，再按需要深入。父级主要导航到直接子级，工具参数由工具自己的说明维护，课程细节由课程上下文维护。

[Hub 架构原文](../hub/guides/架构与维护.md)保留逐级下钻、单一数据源和工具说明分工；[公开版 Hub 入口](../hub/.agent/memory.md)是可直接阅读的导航示例。

### 2. 三件套：区分稳定信息、当前状态和完成历史

- `memory.md`：基本资料、目录导航、规则、已安装插件及读取时机。
- `progress.md`：现在正在做什么、做到哪里、有什么问题、下一步是什么。
- `completed_tasks_log.md`：已经完成的任务、章节、答疑与决定。

新对话先读入口和当前状态，需要追溯时再读历史。推进任务更新进度；完成阶段先记录历史，再清理活跃任务；稳定资料和导航变化更新入口。

### 3. 插件：把特定任务的流程安装到项目

这里的插件是给 AI 执行的文件化工作流程。它有名称、版本、适用类型、读取时机、输入和输出。课程讲解与答疑、ASR 录播整理是当前两个实例。

创建课程时选择上下文类型，再按需要安装插件：

1. 从[规范库索引](../standards/上下文规范/.agent/memory.md)选择适用的插件。
2. 将正文复制到课程自己的 `.agent/plugins/`。
3. 在课程 `memory.md` 登记名称、本地文件、版本、读取时机和课程配置。
4. 遇到匹配任务时才读取对应插件，平时不加载无关正文。
5. 课程专用规则放在本地插件开头的“课程特化规则”，与通用正文分开。

升级时比较源文件与课程副本，定向更新通用部分，保留课程特化。日常工作依靠项目自己的规则和本地插件，不因共享规范库变动而自动改变正在学习的课程。

可以继续新增实验报告、习题整理或其他任务插件，只要说明读取时机、所需资料、执行步骤、产物和写回位置，不必把所有任务都塞入核心规范。

### 4. 笔记规范：对成果提出完整要求

[课件规范](../standards/笔记整理规范/PPT课件笔记整理规范.md)负责前置知识、内容组织、逐页来源、重点、图像与解释；[视频规范](../standards/笔记整理规范/视频图文笔记整理规范.md)负责讲解主线、时间锚点和关键画面；[视频处理流程](../standards/笔记整理规范/视频图文笔记处理流程.md)串联获取、转录、对齐、抽帧和成文。

规范源保存全文。课程可以增加就近特化，而不需要每次从头编写提示词。`workflows/` 中的短版仅用于快速导航，完整要求以上述正文为准。

### 5. 调用指南和 README：让工具可发现、可执行、可维护

Hub 指南给出任务对应的工具、核心命令、运行环境和产物位置；各工具的 README 保存完整参数、安装方式、缓存、重试、运行示例和排错说明。

AI 可以先用调用摘要完成常见操作，需要进一步参数时再读详细说明或 CLI 帮助。脚本负责明确执行，AI 根据内容判断是否看得清、是否需要画面、怎样核对术语和组织知识。

### 6. 资料与成果：保留每一层依据

- 原课件、讲义提供页面与图像依据。
- ASR 原文保留课堂讲授与分块定位。
- 概述快速说明本讲主线、课堂重点及课件映射。
- 详细笔记组织定义、推导、例子、图表和补充解释。
- 图片与 Markdown 同名 `.assets/` 保存，移动材料时链接仍可用。

[真实分治法案例](../examples/algorithm-divide-conquer/README.md)完整保留这些层次。该历史课程使用的是内嵌规则，案例保留原课程上下文；[插件安装示例](../examples/plugin-course/README.md)另行展示当前设计，不把后来的规范套成历史事实。

## 公开版与本机版

原 Hub、课程资料和工具继续在原位置使用。这个仓库是独立公开副本：把认证信息留在环境中，将个人路径改为可配置位置，同时保留相关完整实现和原文说明。原稿路径作为架构示例保留时会在入口说明，公开执行命令则指向仓库内工具。

两个位置不会自动双向同步。公共改动应在比较后单独迁移，避免公开整理直接改变日常环境。
