## ✏️ 伪代码书写规范（全课程通用）

> 来源：ch1 课件 PPT P29

**伪代码（Pseudocode）**：自然语言和编程语言的混合体，兼顾精确性和可读性。

| 规则 | 说明 | 示例 |
|------|------|------|
| **省略变量声明** | 不需要写类型（如 int、float） | 直接用 `r`，不写 `int r` |
| **缩进表示作用域** | for/if/while 的范围靠缩进区分，不用 `{}` | 看代码缩进层级 |
| **`←` 表示赋值** | 区别于数学等号 `=`（判断相等） | `r ← m mod n` |
| **`do` 配合循环** | while 循环写作 `while 条件 do` | `while n ≠ 0 do` |

**标准格式：**

```
Algorithm 算法名(参数1, 参数2, ...)
// 功能说明
// Input: 输入说明
// Output: 输出说明
具体步骤（缩进表示作用域）
return 返回值
```

> 💡 赋值用 `←`，比较用 `=` 或 `==`。与编程语言中 `=` 赋值、`==` 比较的习惯不同。

## 🎧 ASR 概述整理与撰写规范（可选）

当需要对某章/某节课的 ASR 转录文本进行提炼归纳，或在学习新章节前需要快速生成导学概述时，按以下规范执行：

* **文件存放与命名**：
  - 文件放置在 `.agent/asr概述/` 目录下。
  - 各课拆分后的概述文档命名标准为：`[转录asr的日期]_[对应的课件章节/主要内容].md`（如 `2026-03-05_Ch1.md` 或 `2026-03-12_Ch1_算法流程.md`）。
* **读取与整理原则**：
  - 根据项目记忆文档对照关系或用户指令，找到对应的 ASR 转录和课件 PDF，直接使用 `view_file` 读取。必须直接读取 PDF，别转换，不用看笔记。
  - 由于一个章节的课件可能对应多节课（对应多个日期的 ASR 转录文件），**严禁一次性读取多个 ASR 文档**。
  - 必须逐个 ASR 文档读取与处理。先用 `view_file` 读取目标 ASR 和对应课件 PDF，整理追加后，再读取下一个。
* **对照属性规范**：
  每一节课的 ASR 均以一个 **4 列对照表**的形式进行整理追加。列名与具体要求如下（单元格内不使用 `<br>` 换行）：
  - **ASR段号**：转录文件中的分块标识，使用普通的 `[N]` 纯文本格式（不加粗，不带反引号）。1段代表 2.5 分钟。
  - **课件对应**：该 ASR 段号对应 PPT 课件中的页码范围（如 `P24-P27`）。若老师脱离课件讲外话，标记为 `课外` 或 `无对应页码`。
  - **主要内容**：该 ASR 段号区间的授课主题，精炼取一个适合的模块名称。
  - **重点 / 不考 / 不讲**：详细记录该段授课的核心重点、明确不讲或不考的知识点、老师强调的具体逻辑或原理解释，以及相关要求。
* **整理标准**：
  作为 ASR 的概述，必须包含所有 ASR 文件中有价值的内容。整理完成后，后续学习 AI 无需再查看 ASR 转录源文件即可了解课程大概内容。

  讲解要求（所有模式通用）：

  - 注意额外讲解用户可能难以理解、卡住的地方

  ## 📋 三文件维护规则

  ### 文件分工

  | 文件                   | 定位       | 只放                                                 | 不放             |
  | ---------------------- | ---------- | ---------------------------------------------------- | ---------------- |
  | memory.md              | 静态上下文 | 课程信息、大纲、目录结构、学习流程、本维护规则       | 任何会变动的进度 |
  | progress.md            | 当前快照   | 里程碑 + 当前章节（预估/明细/答疑）+ 待办 + 用时参考 | 已完成章节的内容 |
  | completed_tasks_log.md | 历史详档   | 已完成章节的学习明细 + 答疑记录 + 笔记产出           | 当前进行中的内容 |

  ### progress.md 表格体系

  > progress.md 包含 5 张表格，分为持久表和临时表两类。

  | #    | 表名       | 性质               | 列                                         | 说明                                 |
  | ---- | ---------- | ------------------ | ------------------------------------------ | ------------------------------------ |
  | ①    | 里程碑表   | 持久，逐章追加     | 日期 / 里程碑 / 状态                       | 全章级别的状态总览                   |
  | ②    | 预估表     | 临时，每章新建     | 节 / PPT范围 / 预估用时                    | 开始新章节时创建，纯计划用，学完清掉 |
  | ③    | 学习明细表 | 临时，学习时填写   | 日期 / 时间段 / 内容 / 用时 / 备注         | 一行 = 一段连续学习，不绑定小节      |
  | ④    | 答疑记录表 | 临时，学习时填写   | 日期 / 页码或概念 / 困惑点 / 结论          | 记录概念性的误解或混淆               |
  | ⑤    | 用时参考表 | 持久，每章完成追加 | 章节 / 内容量 / 实际用时 / 学习方式 / 备注 | AI 校准预估的参考数据                |

  **表③ 学习明细表**：

  - 一行 = 一段连续学习时间，可以跨小节、可以只学半个小节
  - 时间段为可选（有则写、无则留空），日期 + 用时为必填
  - 备注列收录：讲解模式（逐页/逐小节/整大节）、用时偏差原因、跳过或调整说明
  - 休息可选记录（加一行内容写"休息"即可）
  - 习题学习也记在此表（内容列写"习题"）
  - 同一小节分多天学习：日期写逗号分隔，用时写加法（如 35min (20+15)）

  **表④ 答疑记录表**：

  - 收录标准：用户对概念产生误解或混淆，经辨析后纠正的
  - 不收录纯事实性提问

  ### 记录标准

  > **progress.md 和 completed_tasks_log.md 的记录粒度必须达到：一个新开的对话窗口读完后，能直接接手继续教学，无需额外追问。**

  - **不能只做要点提炼**：记录"学到了哪一节"、"下一节是什么"、"有哪些遗留困惑"
  - **状态要可操作**：当前章节写清楚学到哪里、下一步从哪里继续
  - **上下文要完整**：用户卡住的点、笔记修改情况、待确认事项都要记录

  ### 对话初始化

  AI 每次新对话读完 memory.md 后，必须：

  1. 只读取 `progress.md` 了解当前的里程碑、在学章节、预估表和待办事项。
  2. ⚠️ **绝对禁止在初始化时主动读取 completed_tasks_log.md 或其他课件、转录、笔记等大文件**。
  3. 简要告知用户当前进度。如果有进一步学习或回溯需要，必须**先询问用户需要阅读哪些辅助文件**（如：`completed_tasks_log.md` 历史答疑记录、对应章节的课件 PDF、ASR 转录、已有笔记等），待用户明确回复后再进行读取，避免上下文爆满。
  4. 若本次对话涉及**笔记整理/重写**，必须先读 `.agent/笔记整理指南.md`（子类优先，无子类则读全局基类 `D:\Antigravity-Hub\规范\笔记整理指南.md`），确认规范后再动手。

  ### 迁移 SOP（一章学完时执行）

  1. **表③ 学习明细表 + 表④ 答疑记录表** → 剪切到 `completed_tasks_log.md`
  2. **表⑤ 用时参考表** → 追加一行汇总
  3. **表① 里程碑表** → 该章标 ✅
  4. **清空** progress.md 当前章节区域（表②③④）
  5. **笔记产出** → 在 completed_tasks_log.md 条目末尾列出文件清单

  ### 注意事项

  - **笔记 ≠ 已学完**：笔记是 AI 生成的学习材料，不代表用户已学完。只有用户明确说"学完了"才标记 `[x]`
  - **笔记补充原则**：用户学习中的困惑和解答，应同步补充到笔记中，不删除原始内容，在旁边追加澄清
