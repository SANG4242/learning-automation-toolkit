# 课程任务上下文规范

> 规范版本：v1.1.2
> 创建日期：2026-09-15
> 最后更新：2026-10-11
> 用途：指导以报告、展示、活动、考勤或技能考核为主要状态的大学课程创建任务型 `.agent` 目录
> 运行边界：本规范是规范库中的创建源。创建完成后，实际课程的 `.agent/` 应完整保存运行所需的核心规则和已安装插件，日常运行以课程本地上下文为准。

---

## 核心结构

```text
课程名称/
├── .agent/
│   ├── memory.md                 # 静态课程档案、考核结构、资料索引和维护规则
│   ├── progress.md               # 当前任务、近期节点、持续性要求和待确认事项
│   ├── completed_tasks_log.md    # 已完成、已提交或已参加事项的历史记录
│   ├── plugins/                  # 已安装插件的本地副本（可选）
│   └── context/                  # 较大的课程要求或长期接手资料（可选）
├── ASR转录/                      # 正式可读的完整转录 Markdown（可选）
├── 课件/                         # 课程正式 PPT / PDF（可选）
├── 相关资料/                     # 截图、通知、教材和参考资料等（可选）
├── 作业与报告/                   # 作业、报告及其素材（可选）
├── 展示/                         # 展示文稿、讲稿及相关素材（可选）
└── 活动与考核/                   # 活动记录、训练材料或考核资料（可选）
```

三个核心文件是最小启动集。其余目录只在出现相应内容时创建。`ASR转录/` 只保存正式可读的完整转录 Markdown；原始音视频放在 Hub `temp\语音转录\audio\`，每次任务的转录、分块清单、分块 WAV 和对齐文件集中放在 `temp\语音转录\output\任务名\`；正式课件放入 `课件/`，截图、通知等辅助材料放入 `相关资料/`。

## 上下文维护规则

### 文件分工

| 文件 | 定位 | 只放 | 不放 |
|------|------|------|------|
| memory.md | 静态课程档案 | 基本信息、考核结构、固定要求、资料索引、目录结构、插件索引、本规则 | 当前进度和临时安排 |
| progress.md | 当前快照 | 接手指南、近期节点、活跃任务、持续性要求、待办和待确认事项 | 已完成事项的详细记录 |
| completed_tasks_log.md | 历史记录 | 已提交、已参加、已考核或已取消事项的完成情况、结果、反馈和文件 | 进行中的任务 |

### 事件式写回

1. 新任务、新通知、截止时间、当前状态、下一步或阻塞发生变化时，更新 `progress.md`。
2. 任务已提交、活动已参加、考核已完成或事项已取消时，执行完成归档。
3. 课程基本信息、考核结构、固定要求、目录或资料索引变化时，更新 `memory.md`。
4. 只读查询或简单说明未改变课程状态时，无需写回三个核心文件。

### 活跃任务与近期节点

- 每个需要独立推进的事项使用一个 `### 任务：[名称]` 区块，至少记录目标、要求、当前状态和下一步。
- `近期节点` 汇总仍需关注的截止日期和发生时间；任务归档后同步移除对应行。
- 考勤、训练、签到等重复事项放入“持续性要求”；出现补做、请假或专项准备时，再建立活跃任务。
- 截止时间和要求记录来源。信息未经确认时标注“待确认”，后续获得权威信息后替换。
- 文件已经生成只表示产物存在。提交、参加或完成状态以用户明确说明、平台记录或其他可验证凭据为准。

### 完成归档

1. 将完成事项写入 `completed_tasks_log.md` 顶部，记录实际完成内容和状态。
2. 从 `progress.md` 移除对应活跃任务及近期节点。
3. 更新接手指南、待办、持续性要求和待确认事项。
4. 成果文件保留在课程公开目录中，完成日志只记录路径和必要说明。
5. 实际时间、成绩或反馈未知时保持空缺或标注“待公布”，不补造信息。

### 大型独立交付

当某项报告、课程设计或展示已经形成独立目标、阶段规划、较多资料和验收流程时，可建议建立通用项目上下文。用户明确要求创建，或确认 AI 的创建建议后，再按中央规范入口初始化。课程任务上下文保留：

- 课程中的截止节点和考核要求；
- 独立项目路径或链接；
- 汇总状态、最终提交和结果。

具体执行状态和历史记录由独立项目维护。

### 插件查找与维护

- “已安装插件”是本课程支持插件的唯一索引。当前任务符合读取时机时，读取表中登记的本地插件文件。
- 当前需要的能力未登记，或用户要求安装、升级、移除插件、审查上下文时，读取 `D:\Antigravity-Hub\规范\上下文规范\.agent\memory.md` 的中央插件索引。
- 安装前取得用户确认；确认后将插件源文件复制到 `.agent/plugins/`，并登记名称、本地文件、版本、读取时机和课程配置。
- 升级时保留课程定制并定向修改；移除时同步更新索引，相关成果是否保留另行确认。

### 上下文扩展

较大的课程总要求、评分细则或长期参与规则可放入 `.agent/context/`：

- 一个主题一个文件，并在“上下文索引”中登记用途和读取时机。
- `memory.md` 保留稳定摘要和链接，详细正文维护一份权威版本。
- 当前任务相关时按需读取，不默认加载全部扩展。

### 对话初始化

每次新对话依次读取：

1. `memory.md`，了解课程要求、维护规则和可用资料；
2. `progress.md`，了解当前任务、近期节点和待确认事项。

`completed_tasks_log.md`、`context/` 和插件文件均按当前任务需要读取。

## 创建流程

用户明确要求创建，或确认 AI 的创建建议后，执行以下流程：

1. 收集课程基本信息、考核组成、已知节点、持续性要求和现有资料位置。
2. 完整创建 `memory.md`、`progress.md` 和 `completed_tasks_log.md`，保留模板中的核心章节。
3. 将当前和未来事项写入 `progress.md`；已有完成记录按实际可确认信息写入完成日志。
4. 根据实际文件组织记录目录结构，只创建当前需要的可选目录。
5. 从中央插件索引筛选适用插件，并逐项向用户确认是否安装。

## 迁移规则

### 从课程学习上下文迁移

适用于课程后续主要状态已转为报告、展示、活动或技能考核的情况：

1. 保留课程基本信息、考核要求、目录和资料索引。
2. 将当前交付、活动和考核事项整理为活跃任务及近期节点。
3. 已完成的章节学习与答疑记录继续保留为历史资料，并在新入口中按需链接。
4. 采用课程任务三文件职责维护后续状态。

### 从通用项目上下文迁移

适用于现有上下文实际覆盖整门课程的多项独立考核任务：

1. 将稳定的课程信息和考核结构整理到 `memory.md`。
2. 将当前任务按课程节点、持续性要求和待确认事项重新归类。
3. 保留历史完成记录；大型独立交付可继续作为通用项目，并从课程上下文链接。
4. 更新上下文类型、采用规范版本和最近迁移日期。

迁移采用定向修改，保留现有课程定制和可追溯历史。
