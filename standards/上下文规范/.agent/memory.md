## 规范库文件架构

```text
上下文规范/
├── .agent/
│   └── memory.md                 # 统一入口、全部索引和本维护规则
├── 通用项目/
│   ├── 通用项目上下文规范.md     # 通用项目的完整创建规范
│   └── 插件/                     # 该类型的插件源文件（有需要时创建）
├── 课程学习/
│   ├── 课程学习上下文规范.md     # 课程学习的完整创建规范
│   └── 插件/                     # 该类型的插件源文件
└── 课程任务/
    └── 课程任务上下文规范.md     # 课程任务的完整创建规范
```

### 文件职责

- 每种上下文类型使用一个独立目录，其 `[上下文类型]上下文规范.md` 完整保存该类型的适用边界、核心结构、文件模板、运行规则和迁移要求。
- `插件/` 保存按需启用的流程源文件。插件按主要用途归入一个上下文类型，适用类型由中央插件索引独立登记。
- 同一插件适用于多个上下文类型时，只保留一份源文件，在中央索引的“适用类型”中登记多个类型，不向各类型复制规范源。
- 不预建空的类型目录或 `插件/` 目录。

## 上下文创建流程

1. 读取本文件，根据主要产出选择一个上下文类型。
2. 完整读取所选类型的 `[上下文类型]上下文规范.md`。
3. 从本文件的插件索引筛选适用于该类型和当前项目的插件，并逐项向用户确认是否启用。
4. 按类型规范创建实际项目的核心上下文文件。
5. 将已启用插件复制到实际项目的 `.agent/plugins/`；未安装插件时不创建空目录。
6. 在实际项目的 `.agent/memory.md` 中登记已安装插件的名称、本地文件、版本、读取时机和项目配置。
7. 创建完成后，以实际项目 `.agent/` 中的核心规则和本地插件为日常运行依据。

插件出现在中央索引或项目入口中不表示默认加载。实际项目只在当前任务符合插件读取时机时读取对应本地文件。

### 项目入口的插件信息

“项目支持的插件”指已复制到该项目 `.agent/plugins/`、可由该项目本地运行的插件。每种上下文类型的 `memory.md` 模板必须包含：

1. **已安装插件索引**：登记插件名称、本地文件、版本、读取时机和项目配置；未安装插件时标注“暂无”。
2. **内嵌插件维护规则**：说明如何从本地索引查找和加载插件，以及如何安装、升级和移除插件。

日常工作只根据项目入口查找已安装插件。当前任务需要的能力不在项目入口，或用户要求新增能力、安装插件、升级插件、审查上下文时，读取本规范库的中央插件索引查找适用插件；安装或修改项目前先取得用户确认，不通过扫描目录猜测可用插件。

## 核心规范与插件的边界

### 保留在类型规范

符合以下任一条件的内容保留在该类型的 `上下文规范.md`：

- 创建该类型上下文所必需；
- 决定核心文件的职责、模板或写回方式；
- 适用于该类型的大多数实例；
- 缺少后会导致核心上下文无法独立运行。

### 拆为插件

一项流程同时满足以下条件时，拆为插件：

- 只有部分实例需要；
- 只在明确的任务或活动中触发；
- 具有相对独立的输入、流程和产物；
- 可以明确说明读取时机及读写边界；
- 移除后不影响核心上下文运行。

某项能力适用于多个上下文类型时，在中央插件索引登记多个适用类型，无需写入每种上下文规范。某项插件成为该类型所有实例的必需能力时，将其规则合并回该类型规范，并从插件索引移除。

### 插件文件要求

新增插件应说明：

- 插件名称、版本、用途和读取时机；
- 安装位置与适用前提；
- 需要读取和更新的文件；
- 执行流程和产物位置；
- 与核心规范或其他插件的依赖关系。

已有插件在后续实质修改时逐步补齐，不为统一格式单独重写正文。

## 索引维护规则

### 新增上下文类型

1. 创建 `[类型名称]/[类型名称]上下文规范.md`，文件名必须带类型前缀；固定入口文件 `.agent/memory.md` 除外。
2. 在“上下文类型索引”新增一行。
3. 只有出现实际插件时才创建该类型的 `插件/`。

### 新增插件

1. 根据主要用途放入所属类型的 `插件/`。
2. 在“插件索引”新增一行，登记版本、适用类型、源文件、用途和选择时机。
3. 不在类型规范中重复建立可用插件列表。

### 移动、改名或改变适用范围

- 更新本文件中的唯一索引条目及相关链接。
- 检查受影响的实际项目；项目中的本地插件不随规范源路径变化自动移动。
- 上级 `规范/.agent/memory.md` 只导航到本入口，不展开类型和插件详情。

## 版本与迁移

- 规范和插件分别维护版本号；格式与链接修正升级补丁版本，兼容性新增升级次版本，不兼容的结构或执行变化升级主版本。
- 运行正文保存当前版本与有效规则；版本历史和迁移说明集中保存在源侧维护记录，仅维护时读取。项目副本保留当前规则和项目特化，项目记录简要登记实际升级及成果。已有文件在相关维护时逐步采用此分工。
- 规范源更新不自动覆盖实际项目中的规则或本地插件。
- 迁移已有项目时，先比较版本和变更内容，保留项目定制，再进行定向修改。
- 迁移完成后，更新项目入口记录的规范或插件版本，并按项目自身维护规则记录迁移结果。
- 新增、移动、删除或改变职责后，在发送最终回复前同步更新本文件的对应索引。
