# 视频图文笔记整理规范

> 用途：指导 AI 将视频内容整理为可在 Typora 中独立阅读、便于回看原视频的图文笔记。视频下载、字幕与 ASR、时间定位、抽帧和资源保存按《视频图文笔记处理流程》执行。

---

## 核心执行约束

1. **默认沿视频主线组织**：保持知识依赖、推导、演示和观点转折的先后关系；允许合并重复讲解、归并分散内容，并将后置限定条件移到对应结论附近。
2. **覆盖有效内容**：覆盖实质性知识点、论证、示例、操作、现象、结论、限制条件和重要提醒；压缩寒暄、口头重复、转场和无信息量停顿，不逐句复现字幕。
3. **笔记独立可读**：补全口语中省略的前提、主语、因果和推导步骤。时间戳用于溯源和回看，不能代替正文解释。
4. **字幕需要核对**：字幕和 ASR 主要用于理解讲解及定位时间。术语、公式、代码、数字和专有名词应结合视频画面、上下文或可靠资料核对。
5. **时间锚点分级设置**：开头提供时间路线，大节标注时间范围，关键结论、示例、操作节点和截图标注具体时间点；不要求每段文字都有时间戳。
6. **图片参与讲解**：图片应提供正文难以完整表达的视觉信息，并采用“文字引入—插图—关键点解读”的结构。

---

## 〇、设计原则：从连续讲解到可复习知识

视频笔记的目标不是压缩字幕，而是将连续讲解整理为便于学习和复习的知识结构：

1. **保留讲解脉络**：让读者看清问题如何提出、概念如何建立、结论如何得出。
2. **补足逻辑链条**：将视频依赖语气、手势、画面或上下文表达的关系写清楚。
3. **区分主次**：正文突出可复用的原理、方法和关键结论，重复举例和口头铺垫适当压缩。
4. **保留回看入口**：在真正需要重看片段的位置提供准确时间锚点。

---

## 零、笔记定位

视频笔记是主要学习材料，原视频用于查看动态过程、听取原始表述和核对上下文。笔记需要：

- 自身内容完整，读者不播放视频也能理解主要内容；
- 说明各知识点、步骤或观点之间的关系；
- 保留重要示例、推导、演示结果和限制条件；
- 对值得回看的内容提供时间锚点；
- 选择能补充视觉信息的关键画面并进行解读。

无需完成以下工作：

- 按字幕逐句改写；
- 按固定时间间隔切分正文；
- 为每个讲解片段配图；
- 为普通解释段落逐段添加时间戳；
- 保留不影响理解的口头重复和转场内容。

---

## 一、整理前置：上下文与需求确认

开始整理前，先判断视频类型、笔记用途和读者基础。能够从用户指令、项目上下文或已有进度文件确定的信息，不重复询问。

需要确认或读取的内容包括：

1. 视频来源、本地文件或链接；
2. 笔记的目标目录和用途；
3. 用户特别关注的主题；
4. 是否需要结合课件、已有笔记、考试重点或项目资料；
5. 理解视频所需的关键前置知识。

课程录播还应读取课程项目的就近规范和已安装插件，将教师强调、考试范围、课件页码等课程信息叠加到本规范。

---

## 二、内容定位：AI 助教模式

### 1. 详略原则

- **详写**：核心概念、关键因果、推导步骤、通用方法、容易误解处、重要操作和用户关注内容。
- **适度压缩**：作用相同的多个例子、反复强调的同一结论、能够由上下文直接推出的内容。
- **略去**：寒暄、广告、无关闲聊、口头填充、纯转场和对知识没有影响的失误。

### 2. 事实、原话与补充解释

- 视频明确给出的知识和结论写入正文，并保留必要的来源时间。
- 讲解者具有辨识价值的原话可简短引用，注明时间点。
- AI 补充的背景、解释和纠错应与视频原意区分，不将补充内容伪装成视频原话。
- 视频内容存在疑点时，先核验；无法确认时明确标注待核验，不自行补成确定事实。

### 3. 内容重组边界

可以进行：

- 合并相邻的同义讲解；
- 将分散出现的同一知识点集中说明；
- 将后面补充的条件移到相应结论附近；
- 把连续演示整理成清晰步骤；
- 补充必要的定义、背景和中间推导。

以下内容应保持原有逻辑顺序：

- 推导中的前提、过程与结论；
- 操作或实验的状态变化；
- 问题发现、排查和解决过程；
- 反例、观点转折以及讲解者对前述内容的修正。

调整正文顺序后，时间锚点仍应指向实际来源位置。

### 4. 不同视频类型的侧重点

- **知识讲解类**：突出概念、因果、推导、例题和易错点。
- **软件操作类**：围绕任务目标，写清操作顺序、界面位置、参数、结果和异常情况。
- **实验演示类**：写清条件、步骤、观察现象、结果和误差来源。
- **访谈或观点类**：按议题组织，保留观点归属、论据和必要上下文。
- **课程录播类**：结合课件页码、教师强调、考试信息和课程进度整理。

---

## 三、整理前的问题清单

只询问无法从现有上下文判断且会显著影响成文结果的问题：

### 必要时确认

1. 这份笔记用于系统学习、快速复习、操作复现，还是提取观点？
2. 是否有需要重点保留或深入解释的部分？
3. 是否需要结合课程课件、考试范围或已有笔记？

### 视内容确认

4. 代码、公式或操作步骤需要展开到什么程度？
5. 是否需要保留讲解者原话或观点归属？
6. 对较长视频，是整理全部内容还是指定章节？

## 四、笔记结构模板

结构根据视频内容调整，默认采用以下框架。

### 1. 开头部分

#### 标题与来源信息

标题应概括实际主题。原标题冗长、营销化或不能说明内容时，可重新拟定笔记标题，并在来源信息中保留原视频标题。

至少记录能够确认的信息：

```markdown
> 来源：[视频原标题](视频链接)
>
> 作者：作者名　时长：HH:MM:SS
```

本地视频没有公开链接时，记录原文件名；发布日期等信息只在有助于判断内容时效性时保留。

#### 一句话概览

用一两句话说明视频处理的核心问题、给出的主要方法或形成的关键结论。

#### 知识地图

开头保留两张作用不同的知识地图：

1. **详细知识地图**：使用 Mermaid 流程图（Flowchart）展示，覆盖到笔记的微观小节标号。子节点较少时可用 `graph TD`；子节点较多、横向较宽时使用 `graph LR`，避免在 Typora 中压缩得难以阅读。
2. **极简知识地图**：使用 Mermaid 思维导图（Mindmap）展示，只标注大节及其核心主题，帮助读者快速建立整体概念树。

#### 演进逻辑链

紧接知识地图，用文字串联各大节之间的因果、依赖和演进关系，说明视频怎样从问题出发推进到方法、示例与结论。逻辑链应对应正文结构，不能只复述目录标题。

#### 内容目标

列出视频试图回答的问题，或读完笔记后应掌握的内容。短视频内容单一时可与概览合并。

#### 时间路线图

中长视频、主题较多或存在明确章节时，提供时间路线图：

```markdown
| 时间 | 主题 | 主要内容 |
| --- | --- | --- |
| 00:00–03:20 | 问题引入 | 建立背景与目标 |
| 03:20–11:10 | 核心概念 | 解释定义与原理 |
| 11:10–24:40 | 方法与示例 | 展示应用过程 |
```

短视频只有少量连续主题时，可用一段话或简短列表代替表格。

### 2. 正文部分

#### 组织顺序

默认按视频主要讲解顺序展开。标题反映知识结构，不机械使用“第一段视频”“第二段视频”等时间切块名称。

#### 大节时间范围

较长视频的大节标题标注覆盖范围：

```markdown
## 三、核心方法（08:42–15:30）
```

一个大节整合多个分散片段时，在导读或相关段落分别标注来源时间，不编造连续范围。

#### 思维链条与阅读体验

1. **逻辑链导读（必须）**：每个大节开头用一段引用块说明为什么讲这一部分、它与前后内容的关系，以及本节将怎样展开。
2. **大节导读的自适应结构化拆解**：当大节包含多个小节或知识点时，在导读下方把小节归纳为若干组块，并梳理组块之间的演进脉络或结构关系。
   - 展开形式根据内容决定：工程和操作类可采用“问题—方案—结果”，数理推导类可展示推导链，概念类可展示分类或对比关系。
   - 每个组块标注对应的笔记小节编号或范围，方便读者在宏观结构与正文细节之间定位。
   - 大节结构简单时保留逻辑链导读，省略组块拆解。
3. **连续讲解**：用连贯叙述串联知识点，说明讲解如何从前一结论推进到下一问题，不堆砌定义或字幕片段。
4. **补足隐含关系**：将视频依赖语气、手势、动画、板书过程或上下文表达的关系写成明确文字。
5. **一句话锚定（建议）**：较长小节结尾用一句话概括本节解决的问题和形成的结论。
6. **有效内容完整性（必须）**：整理完成后对照字幕和画面检查，确认实质性知识点、论证、示例、操作、限制条件和结论均已覆盖。

#### 关键时间点

以下内容适合标注具体时间：

- 首次给出的核心定义或结论；
- 关键推导、示例和反例；
- 操作步骤中的重要节点；
- 实验现象和结果出现的时刻；
- 讲解者的重要限定、纠错或总结；
- 插入笔记的截图。

时间点可写在句中、段末或图片描述中，例如：

```markdown
视频在 `09:35` 通过动态图展示了数列进入邻域后的状态。
```

普通解释段落无需连续堆叠时间戳。

### 3. 结尾部分

根据视频类型选择以下内容：

- 核心要点回顾；
- 方法或操作步骤清单；
- 易错点与限制条件；
- 需要继续查证的问题；
- 与后续内容的关系。

简单视频可用一段总结结束，无需机械套用全部栏目。

## 六、视觉与排版

1. 使用清晰的 Markdown 标题层级，层级服务于内容结构。
2. 核心术语和关键结论可适度加粗，避免连续大段加粗。
3. 代码块注明语言；界面路径、命令和短代码使用行内代码格式。
4. 数学表达式使用 Typora 可渲染的 LaTeX 格式。
5. 对比信息优先使用表格；连续步骤优先使用有序列表。
6. Mermaid 仅用于确实适合重建的流程、层级和关系，不强行为复杂视频画面重新制图。
7. 引用块用于原话、补充说明或阶段导读时，应让读者能够分辨其作用。

## 七、图片处理策略

截图的定位、抽取、筛选、裁剪、命名和保存按《视频图文笔记处理流程》执行。本节规定视觉内容采用什么形式，以及图片如何融入正文。

### 1. 图表处理方式

AI 根据内容特点选择便于准确表达和讲解的形式：

- **视频截图**：画面本身包含重要视觉信息，或重建会损失布局、细节、动态结果和原始语境时使用。
- **Mermaid / HTML**：流程、树形结构和层级关系等内容适合用节点和连线重新表达时使用。
- **Markdown 表格 / 文字 / 公式**：参数对比、分类列表、伪代码、公式推导等以结构化文本表达更清楚时使用。

选择标准是信息准确、便于讲解和复习。视频画面合适时优先保留截图，不为避免截图强行重建；文字或结构图表达更清楚时也不机械截图。

### 2. 截图融入规范

**核心原则**：截图是讲解的视觉素材，需要与前后正文共同表达知识点。插图后应把画面中的关键信息、变化及其意义写清楚，使读者知道看哪里、看到了什么，以及它与当前结论有什么关系。

采用以下写作模式：

1. **文字先铺垫**：在截图前交代背景、问题、观察目标，或说明为什么需要看这个画面；
2. **插入截图**：选择信息完整、清晰且与当前讲解对应的画面；
3. **文字做解读**：指出画面中的关键区域、数据、步骤或状态变化，解释其意义，并在需要时引出下一步。

动态过程无法由单帧表达时，可以使用少量连续画面。每张图应代表不同状态，并通过文字说明状态如何变化。

以下写法不合格：

- 插图后只写“如图所示”，没有指出具体信息；
- 图片与前后文字缺少对应关系；
- 多张近似画面重复同一信息；
- 用截图替代本应写入正文的定义、步骤或结论。

### 3. 图片引用

图片放在与 Markdown 同名的 `.assets/` 目录中，使用相对路径：

```markdown
![画面内容（视频 09:35）](笔记名.assets/01_画面内容.jpg)
```

图片描述应说明画面内容并保留准确时间点。

## 八、最终检查

交付前检查：

1. 视频中的有效内容是否覆盖，是否遗漏关键论证、示例、操作、限制条件或结论；
2. 正文是否形成连贯知识结构，能否脱离视频独立阅读；
3. 内容重组是否保持原意和必要的先后关系；
4. 时间路线、大节范围、关键时间点和截图时间是否准确且相互一致；
5. 术语、公式、代码、数字和专有名词是否完成核对；
6. 每张图片是否补充了有效视觉信息，前后文字是否完成具体解读；
7. Markdown 标题、表格、公式、代码块和图片路径能否在 Typora 中正常显示；
8. `.assets/` 是否只保留最终采用的资源；
9. 视频标题、作者、链接、时长等来源信息是否准确；
10. 课程或项目场景是否满足就近规范和已安装插件要求。

常见问题包括：把字幕摘要当成笔记、按固定分钟机械切段、堆叠时间戳、照抄字幕错误、为每段配图、插图后缺少解读，以及重组内容后时间锚点失真。
