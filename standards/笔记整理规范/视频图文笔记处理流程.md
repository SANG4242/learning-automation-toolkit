# 视频图文笔记处理流程

> 用途：指导 AI 获取和处理视频素材，聚合调用视频下载、字幕、ASR、时间定位、抽帧、选图和资源保存能力。最终笔记的内容取舍、正文结构、时间标注与图文表达按《视频图文笔记整理规范》执行。

## 一、适用范围与触发方式

适用于以下场景：

- 用户提供 YouTube、B 站等视频链接，要求整理笔记、总结为图文内容或保留关键画面。
- 用户提供本地视频，要求根据讲解内容制作图文笔记。
- 课程录播需要结合课程上下文、课件或教师授课重点整理。

用户说“把这个视频整理成图文笔记”“根据这个视频做笔记并配上关键截图”等自然语言即可触发，无需逐项指定工具。

本流程是视频素材处理入口。所有视频笔记任务同时执行《视频图文笔记整理规范》；课程场景还需读取课程项目已安装的插件和就近笔记整理规范。

## 二、职责边界

### AI 负责判断

- 哪些知识点需要画面辅助表达。
- 截图对应哪段原文和时间范围。
- 候选帧中哪一张信息最完整、清晰。
- 图片是否需要裁剪以及最终保存哪一张。

### 工具负责执行

- 下载视频和平台已有字幕。
- 默认执行本地 ASR 转录与精细时间对齐。
- 根据本地转录原文或句子 ID 查询时间戳。
- 按指定时间抽取候选帧。
- 保存中间文件和最终图片。

不要求预先开发总控 Python 脚本。AI 按本文档串联现有工具；以后机械步骤形成稳定重复模式时，再评估是否封装脚本。

## 三、输入与产物

### 输入

至少提供一项：

- 视频链接；
- 本地视频文件。

按需确认或从当前项目上下文确定：

- 笔记用途和关注重点；
- 最终笔记存放位置；
- 是否需要结合课程课件、考试重点或已有笔记。

### 最终产物

```text
笔记名.md
笔记名.assets/
├── 01_主题.jpg
├── 02_主题.jpg
└── ...
```

笔记中保留可确认的视频标题、链接等来源信息。图片使用相对路径引用，确保 Markdown 与 `.assets/` 一起移动后仍可正常显示。

### 中间产物

下载的视频、字幕、ASR 结果和候选帧默认放在：

```text
D:\Antigravity-Hub\temp\视频图文笔记\任务名\
```

最终只将选中的图片复制到 `笔记名.assets/`。候选帧和其他中间文件不混入最终笔记资源目录。

## 四、执行流程

### 1. 确定笔记上下文

1. 判断是普通兴趣视频、课程录播还是已有项目资料。
2. 读取本目录 `.agent\memory.md`，并组合执行《视频图文笔记整理规范》和本流程。
3. 若目标目录存在就近定制的笔记整理规范或已安装插件，优先读取并叠加其要求。
4. 明确最终笔记路径；无法从用户指令和项目上下文确定时再询问用户。

### 2. 获取视频与字幕

网络视频使用 `yt-dlp`。优先按 Hub 音视频工具指引中的已登记命令调用；运行异常或需要未登记参数时，再读取 `工具脚本\yt-dlp\README.md`。

同时尝试获取：

- 可供抽帧的视频文件；
- 人工字幕或自动字幕；
- 可确认的标题、链接等来源信息。

本地视频直接进入下一步。

### 3. 生成本地转录并对照字幕

视频笔记默认使用本地 Qwen3-ASR 建立统一的文字和时间定位基线：

1. 调用 `transcribe_qwen_vllm.py`，在 `Hub\temp\语音转录\output\任务名\` 生成 `transcript.md`、`chunks.json` 和 `chunks\`；
2. 调用 `align_qwen.py`，在同一任务目录生成 `alignment.jsonl` 和 `sentences.jsonl`；
3. 后续使用该任务目录的 `sentences.jsonl` 按句子 ID 或原文定位截图时间。

平台字幕同步获取并保留，用于与本地 ASR 对照、补漏和纠正专有名词。确认质量较高的人工字幕可以作为正文的重要参考，但不跳过本地 ASR 和精细对齐。平台自动字幕主要作为辅助来源。

常见平台字幕可能是 SRT、VTT 或 B 站 JSON。无需为了形式统一而机械转换；只有对照或后续工具无法直接读取时，才转换为短句记录。B 站 JSON 可调用 `工具脚本\语音转录\bilibili_json_to_txt.py`。

使用文字材料时按以下原则核对：

- 本地 ASR 提供统一转录文本、句子 ID 和精细时间戳；
- 人工字幕用于补充断句、专有名词和人工校订内容；
- 平台自动字幕用于交叉核对可能的漏听或误识别；
- 术语、公式、代码、数字和专有名词最终结合视频画面、上下文或可靠资料确认。

数学、代码、外语术语密集的视频尤其需要抽查。各类转录都可能把希腊字母、上下标、公式和变量名识别成发音相近的普通词，不得直接照抄进笔记。

具体命令以 `工具脚本\语音转录\README.md` 和 Hub 音视频工具指引为准。

### 4. 分段读取并建立素材映射

1. 按视频章节或语义段落分批阅读字幕、转录，不一次处理过长内容。
2. 按《视频图文笔记整理规范》确定当前批次的知识结构和内容取舍。
3. 同步记录知识点、字幕原句或句子 ID、时间范围及可能需要的截图位置。
4. 截图只补充有视觉信息的内容；纯口述观点能够清楚写成文字时，通常不截图。

### 5. 判断截图位置

优先考虑以下画面：

- 结构图、流程图、数据图表和空间关系；
- 软件界面、操作步骤、设置位置和运行结果；
- 代码画面中与讲解直接相关的关键部分；
- 实物演示、实验现象和前后状态变化；
- 转录无法表达、但画面提供关键信息的内容；
- 讲解者明确提示“看这里”“如图所示”“注意这个位置”的内容；
- 逐步书写的板书、推导和动画，在讲解完成后形成的完整状态。

通常不保留：

- 与知识内容无关的讲解者头像；
- 转场、模糊、字幕遮挡严重或信息残缺的画面；
- 只重复笔记文字、没有新增视觉信息的画面；
- 多张内容近似且没有必要分别展示的画面。

为每个待截图位置记录：

- 对应知识点；
- 可用于时间定位的原句或句子 ID；
- 截图理由；
- 预计插入的笔记位置。

这份记录属于执行过程，可直接保留在当前任务上下文中；内容较多时再存入任务临时目录，无需作为最终交付文档。

### 6. 定位准确时间

- SRT、VTT 等字幕已有起止时间时，直接使用对应字幕段的时间范围。
- ASR 结果使用 `query_timestamp.py`，按句子 ID 或原文片段查询。
- 一句话跨越多个字幕段时，取覆盖该表达的完整时间范围，并结合上下文判断画面出现的先后。

截图时间不机械等于说出关键词的瞬间。讲解者可能先切换画面再讲解，也可能讲完后才展示结果。对于逐步板书、动画演示或操作过程，定位对象应是整个知识点的讲解区间，优先检查讲解后段和结束后的稳定画面。

### 7. 抽取候选帧

每个知识点先按讲解区间抽取 3～5 张候选帧，通常覆盖：

- 画面首次出现关键信息的时刻；
- 讲解中段；
- 板书、动画或操作接近完成的时刻；
- 讲解结束后的稳定画面；
- 必要时向相邻字幕段继续扩展。

短促静态画面可在目标时间前后 1～3 秒取样；持续数十秒甚至数分钟的累积板书，应覆盖整个讲解区间，不能只围绕单句字幕取样。

单帧抽取可直接使用 FFmpeg：

```powershell
ffmpeg -v error -ss "HH:MM:SS.mmm" -i "视频文件" -frames:v 1 -q:v 2 "候选帧.jpg"
```

候选帧按知识点分组并使用有序名称，保存在任务临时目录。若首批候选帧处于转场、动画未完成或信息被遮挡，应围绕该时间继续补抽，不凭时间戳直接选图。

### 8. 查看并筛选候选帧

AI 必须实际查看候选图片后再选择。选择标准依次为：

1. 关键信息完整，逐步板书或动画已经达到适合静态阅读的完成状态；
2. 文字、公式和图形清晰；
3. 与对应笔记内容一致；
4. 没有转场、全屏提示字、鼠标提示、弹幕或字幕造成的关键遮挡；
5. 同等信息下构图更便于阅读。

画面包含多余边缘、播放器控件或大面积无关区域时，可按需裁剪；裁剪后仍需保留理解所需的标题、图例、坐标或界面上下文。

### 9. 保存最终图片

1. 将选中的图片复制到 `笔记名.assets/`。
2. 使用有序且能说明内容的文件名，例如 `01_系统总体结构.jpg`。
3. 记录图片的准确视频时间和预计插入位置。
4. 提供可直接用于正文的相对路径，例如：

```markdown
![系统总体结构（视频 09:35）](笔记名.assets/01_系统总体结构.jpg)
```

5. 图片在正文中的引入和解读按《视频图文笔记整理规范》执行。

### 10. 素材处理检查

完成素材处理后检查：

- 视频、字幕或 ASR 结果是否可用；
- 知识点、原文、时间范围和候选帧是否能够相互追溯；
- 最终图片是否经过实际查看和筛选；
- 图片时间和文件名是否准确；
- Markdown 相对路径能否在 Typora 中正常打开；
- `.assets/` 中是否只保留最终采用的资源；
- 视频标题、链接等来源信息是否准确。

## 五、课程场景扩展

课程录播使用同一条全局工作流，并额外叠加课程项目已有规则：

- `ASR录播整理` 插件负责录播日期、课件页码、教师侧重点和“不讲/不考”等课程信息。
- 课程就近笔记整理规范负责章节结构、详略、页码标注和考试导向。
- 《视频图文笔记整理规范》负责视频笔记的通用成文要求。
- 本流程负责视频获取、文字来源选择、时间定位、候选帧筛选和图片资源保存。

各文档只维护自己的职责，不复制完整流程。

## 六、以后何时考虑聚合脚本

出现以下情况时，再评估编写总控脚本：

- 下载视频、检查字幕、创建目录和转换字幕被稳定重复；
- 输入、输出和失败处理已经固定；
- 手工串联命令明显成为主要耗时或错误来源。

总控脚本可自动化机械步骤，但截图价值判断、候选帧视觉筛选和图文讲解仍由 AI 完成。
