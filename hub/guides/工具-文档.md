# Hub 工具使用指引：文档

读取时机：整理笔记、PDF/Word/PPT 阅读或转换、MinerU 解析、Quarto 报告出版、PDF 制作与视觉验收时。相对资源路径以 `D:\Antigravity-Hub` 为基准；`Notes\` 指 `D:\TJU-Notes\`，`Hub\` 指 `D:\Antigravity-Hub\`。

| 任务类型 | 执行前必读 |
| --- | --- |
| 整理笔记 | 先读取 `规范\笔记整理规范\.agent\memory.md`，按资料类型选择其中登记的专项规范或处理流程；项目存在就近定制规范时优先使用 |
| 文档转换（MinerU） | 统一输出到 `Hub\temp\MinerU转换\`。`<br>`① **云端 API**：详见 `工具脚本\README.md`。⚠️ 官方 API 高峰期排队 500+ 人，优先使用本地版。`<br>`② **WSL 本地 VLM**：WSL 本地 GPU 推理，无排队。命令 `wsl -d Ubuntu -- bash /mnt/d/TJU-Notes/个人项目/MinerU文档解析/start_mineru.sh "/mnt/d/路径/文件.pdf"`。支持多文件（空格分隔）、自动缓存检查，生成路径编码命名与 Typora 风格 `.assets`（与云端版输出格式一致）。首次启动需 ~40s 加载模型，后续每页约 4s。详见 `Notes\个人项目\MinerU文档解析\README.md`。 |
| 办公文档处理 | 脚本在 `工具脚本\文档格式转换\`：`docx2pdf.py` 默认 WPS，`ppt2pdf.py`、`doc2img.py`、`ppt2img.py` 默认 Microsoft Office（Word 或 PowerPoint）。四个入口支持 `.doc`/`.docx` 或 `.ppt`/`.pptx` 的多文件、目录及通配符输入，可用 `--engine wps`、`--engine office`、`--engine libreoffice` 或 `--engine auto` 选择引擎；auto 按 WPS → Office → LibreOffice 的可用性选择，转换失败直接报告。示例：`python 'D:\Antigravity-Hub\工具脚本\文档格式转换\doc2img.py' 'D:\资料\“申请表”.doc' --engine wps`。保留原件，COM 只读打开并禁用宏；转换成功后更新目标 PDF。默认输出到 `Hub\temp\`，转 PDF 指定 `-o` 目录时保留原名，`--names` 可指定 PDF 名或图片子目录名；图片支持 `-q` 和 `--target`。PDF 缓存区分实际引擎，重转后图片自动刷新；`--force` 强制重转。四个入口全部成功返回 0，转换失败返回 1，参数错误返回 2；COM 超时显示最后记录阶段，应用可能仍在运行，须确认自动化实例后处理。其他格式使用 LibreOffice 无头模式。详细参数、依赖、验证结果及排错见 `工具脚本\文档格式转换\Word文档转换工具说明.md`，常规参数可查询对应 CLI 的 `--help`。 |
| Markdown/Quarto 报告出版 | 系统已安装 Quarto CLI 1.10.18，可直接在 CMD/PowerShell 调用，并内置 Pandoc 3.10 与 Typst 0.15.1。用于将 `.qmd`/Markdown 构建为 DOCX、Typst PDF 等格式；核心命令：`quarto render <文件或项目> [--to docx|typst]`，示例：`quarto render "报告.qmd" --to docx`、`quarto render "报告.qmd" --to typst`。DOCX 外观由项目内 `reference-doc` 控制，PDF 外观由 Typst 参数或模板控制；默认模板只能生成通用版式，复杂 Word 对象与两种输出的完全同版不受保证。版本检查：`quarto --version`、`quarto pandoc --version`、`quarto typst --version`。PDF 制作完成后执行下方“PDF 制作后的视觉验收”。 |
| PDF 处理 | ① view_file 优先直接查看 PDF（该工具会返回截图）；② 不支持或需查看已有的拼接图/单张图时，直接运行 `python "D:\Antigravity-Hub\工具脚本\PDF转图片\pdf2img.py" "文件.pdf"`（通过其内置的缓存检查输出路径，禁止手动翻找/检索 temp 目录）；③ 优先查看**拼接版**（每张含多页，效率高）；④ 拼接版看不清时再查看**单张版**（每页一张图，清晰度更高）；⑤ 转换输出路径文件夹名称是全下划线扁平命名的，使用时必须直接复制脚本输出的完整路径，严禁脑补路径层级或将下划线错打为反斜杠 |
| PDF 双语翻译 | 基于 BabelDOC 的保留排版双语翻译工具（pdf2zh-next）。默认生成 `-dual.pdf` 双语对照版与 `-mono.pdf` 纯中文版。核心命令：`pdf2zh "文件.pdf"`。常用参数：指定输出 `--output "目录"`、指定页码 `--pages 1-3`、仅输出双语 `--no-mono`；自带免费翻译通道，支持自定义大模型（`--gemini --gemini-model "gemini-2.5-flash" --gemini-api-key "KEY"`、`--deepseek --deepseek-api-key "KEY"` 或 `--openaicompatible --openai-compatible-base-url "URL" --openai-compatible-api-key "KEY" --openai-compatible-model "MODEL"`）；启动图形界面：`pdf2zh --gui`。命令已注册至全局 PATH，开箱即用。详见 `工具脚本\PDF翻译\README.md`。 |

## PDF 制作后的视觉验收

适用于新建、排版、转换或修改后交付的 PDF，包括 Quarto + Typst 输出。

1. 生成后确认目标 PDF 已实际更新，再按上表“PDF 处理”查看真实页面；编译成功和文本检查仅作为基础检查。
2. 先查看全部页面的拼接预览，检查完整页面的布局、留白与分页；目录、长文本表格及其他细节看不清时，放大对应单页。重点核对字体与缺字、文字重叠或裁切、表格列宽与换行、跨页表头、图片比例、目录层级与页码、配色与可读性。
3. 发现问题后调整排版并重新生成，复查受影响页面及整体分页，直到最终版通过视觉检查再交付；正文改动遵循用户授权。
4. 每次复查使用当前 PDF 对应的新预览。原路径重新生成时，用 `--force` 刷新单页图；拼接图仍命中旧缓存时，查看最新单页图或使用 `-o` 与 `--names` 生成新的预览目录。以脚本实际打印的路径为准。
5. 无法查看实际页面时，如实说明视觉验收尚未完成。
