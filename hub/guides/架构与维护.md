# Hub 架构与维护

读取时机：新增、修改 Hub 内容、索引、工具登记或 `.agent` 上下文时。

本文从 Hub 入口迁入。下文原文中的“本文件”指 `D:\Antigravity-Hub\.agent\memory.md` 及其按需分层体系；“全局导航”仍在入口，“关键词速查”位于同目录 `知识速查.md`，“工具使用指引”位于同目录 `工具-*.md`，“temp 文件规范”位于 `临时文件.md`。维护时更新对应正文所在文件；相对资源路径仍以 `D:\Antigravity-Hub` 为基准，`Notes\` 指 `D:\TJU-Notes\`，`Hub\` 指 `D:\Antigravity-Hub\`。

### memory.md 编写规范

每个 `.agent/memory.md` 文件遵循**层级委派、逐级下钻**的原则：

| 规则 | 说明 |
| --- | --- |
| **只管直系子级** | 目录树仅展开到当前目录的直接子文件夹，不得展开下一层的内部文件结构 |
| **细节下放** | 子文件夹内部的文件列表、操作规范等细节，由该子文件夹自己的 `.agent/memory.md` 负责维护 |
| **父级只做路标** | 父级 memory 对子模块的描述应是一句话概括 + 路由标签（帮助命中的关键词） + 指明"详见该目录下的 `.agent/memory.md`"。路由标签不视为冗余 |
| **新增只改一处** | 普通项目或子模块只在直接父级的 memory 中登记；新增领域或用户明确要求全局快捷入口时，再按“全局导航表维护”更新 Hub |
| **导航不越级** | 目录 memory 导航表中，父级不直接指向孙级目录，而是通过中间层逐级路由（此规则不约束本文件的「全局导航」和「关键词速查」等扁平索引） |

### 设计原则

| 原则 | 做法 |
| --- | --- |
| **单一数据源** | 同一信息只存一处，其他地方用链接引用 |
| **单点维护** | 新增知识笔记时，只更新 `Notes\日常记录\knowledge\.agent\memory.md` 的文件索引；新增排错文件时，更新 `知识速查.md` 的关键词索引 |
| **两层索引** | 「全局导航」按领域路由到入口 memory；「关键词速查」按关键词直达具体条目，两者不重叠 |
| **按性质归位** | 判断文件放哪时，看它是什么性质（排错/知识/脚本/规范），同类内容放同一处 |

### 工具索引与说明分工

| 位置 | 职责 |
| --- | --- |
| **全局导航** | 仅登记领域级 `.agent/memory.md` 入口；工具及其 README 不进入此表 |
| **本 Hub 资源索引** | 只概述 `工具脚本\` 等直属目录，不展开具体工具 |
| **工具使用指引** | 每个工具或工具集保留一条可直接执行的简要入口，记录功能、核心命令、默认输出、运行环境、认证方式和已知限制；常规参数与不确定选项通过对应 CLI 的 `--help` 查询；工具明确不支持的能力直接写明 |
| `工具脚本\README.md` | 按直属子目录索引工具集，每个工具集只保留一行，不重复内部工具参数 |
| 工具目录 `README.md` | 详细用法的权威来源，记录安装结构、参数示例、输出、验证、排错和更新方法 |
| **项目工具入口** | 仅供该项目使用的工具，可在项目 `memory.md` 保存调用摘要；复用公共工具时引用对应工具使用指引 |
| **已有知识速查** | 知识类关键词指向 `Notes\日常记录\knowledge\.agent\memory.md`；排错和资料条目按关键词索引；工具类关键词指向已有工具使用指引，尚未登记的工具保留路径导航 |

公共工具的调用摘要统一保存在对应 `工具-*.md`，详细用法保存在工具目录 `README.md`；Hub `memory.md` 只登记主题导航和读取时机。新增公共工具时更新其直属父级 `README.md` 和对应工具使用指引；新增指引主题时再更新 Hub 入口。

### 内容分类标准

| 性质 | 去哪 | 判断方式 |
| --- | --- | --- |
| 出了问题→排查→解决 | `Hub\排错经验\` | 有"问题+解决方案"结构 |
| 学到的知识/工具使用指南 | `Notes\日常记录\knowledge\` | 概念、原理、操作指南 |
| 可执行的脚本/工具 | `Hub\工具脚本\` | .py/.bat/.ps1 等可运行文件 |
| AI/笔记行为规范 | `Hub\规范\` | 约束 AI 或笔记格式的规则 |

> **工具调用摘要编写规范**：公共工具使用指引和项目专用工具摘要应包含简介、核心参数、运行示例及必要的环境与限制，使调用者能直接完成核心操作；详细参数和维护流程引用工具目录 `README.md`。Hub `memory.md` 保存指引主题、路径与读取时机。

## 本文件使用与维护

> AI 每次新对话首先阅读本文件，建立全系统的内容分布印象。

### 索引机制说明

本文件包含两层索引，各司其职、互不重叠：

| 索引 | 用途 | 适用场景 |
| --- | --- | --- |
| **全局导航** | 按领域路由到入口 memory，再沿层级下钻 | 用户的问题属于某个大领域 |
| **关键词速查** | 按关键词定位知识库入口、排错资料或工具使用指引 | 具体的知识、排错、资料或工具查询 |

### 新增内容时

- **新规范**：放入 `规范\`
- **新工具/脚本**：公共工具放入 `工具脚本\`，更新直属父级 `README.md` 和对应工具使用指引；项目专用工具由项目入口登记调用摘要
- **新排错经验**：放入 `排错经验\` 对应子目录，在关键词速查表追加关键词
- **新知识/指南**：放入 `Notes\日常记录\knowledge\YYYY-MM\`，只更新 `Notes\日常记录\knowledge\.agent\memory.md` 的文件索引
- **新账号/密钥**：放入 `用户信息\`
- **新工具输出类型**：在 `temp\` 下新建子文件夹
- **新分类**：可以直接在 Hub 根目录新建文件夹

### 全局导航表维护

- **新增领域**：在 Hub 全局导航表新增一行（领域 + 入口 memory + 路由关键词）。
- **已有领域下新增项目**：只更新项目直接父级的 memory，由现有领域入口逐级定位。
- **全局快捷入口**：用户明确要求时，在 Hub 全局导航表对应领域追加路由关键词；项目路径仍由直接父级维护。
- **删除/改名**：更新直接负责导航的父级；影响已登记的 Hub 领域入口或快捷关键词时，同步对应条目。

### 关键词速查表维护

- **收录标准**：知识库入口、排错经验、工具使用指引及其他资料；逐篇知识笔记的路径由知识库入口维护；尚未在工具指引登记的工具可保留路径导航
- **不收录**：纯领域级概念（已由全局导航的路由关键词覆盖）
- **格式**：`关键词1、关键词2` → `所在目录路径`

### 修改本文件时

- 保持结构清晰，使用表格
- 重大变更需在 `用户信息\rules_archive\` 留存档

### 新项目的 `.agent`

- 项目专属上下文放项目目录下的 `.agent\memory.md`
- 全局规则引用本文件，不要复制粘贴
